# Skills 디렉토리 가이드

## 스킬 구조

각 스킬은 `skills/<skill-name>/` 디렉토리에 위치한다.

```
<skill-name>/
├── SKILL.md          (필수) YAML frontmatter + 마크다운 본문
├── evals/            (선택) 테스트 케이스
│   └── evals.json
└── references/       (선택) 참조 문서
```

## SKILL.md frontmatter 규칙

```yaml
---
name: <skill-name>       # 디렉토리명과 동일
description: <트리거 설명>  # 한국어, 1-3문장, "언제 사용하는지"를 구체적으로
---
```

- description은 Claude가 스킬을 호출할지 결정하는 핵심 필드다. 모호하면 트리거가 안 된다.
- 한국어 스킬이면 description도 한국어로 쓴다.

## 스킬 간 참조

스킬이 다른 스킬의 포맷을 따를 때는 "X 스킬과 동일한 포맷을 따른다"라고 명시하되, 핵심 필드는 인라인으로 포함한다. 다른 스킬을 읽어야만 실행 가능한 상황을 만들지 않는다.

## references/ 작성

- 질문 단위로 파일을 나눈다. 한 질문에 답하는 데 필요 없는 내용이 같이 딸려오면 분할이 잘못된 것이다.
- 항목은 자급자족하게 쓴다. SKILL.md → 참조 파일 1개, **2홉** 안에 답이 나와야 한다.
- 같은 정보를 두 파일에 쓰지 않는다. 어느 파일이 무엇을 소유하는지 정해두고 나머지는 가리키기만 한다.
- 미리 잘게 쪼개지 않는다. 항목이 커지면 그때 나눈다.

## evals/

형식은 스킬 성격에 맞춘다. 정답이 고정된 스킬이면 `evals.json` 같은 케이스 목록이, 라우팅·판단이 중요한 스킬이면 서술형 시나리오가 낫다.

`ui-references`가 쓰는 형태:

- `evals/scenarios.md` — 프롬프트 + 기대 로드 파일 + 채점 기준. 서브에이전트로 실행하고 트랜스크립트로 채점한다. **기대 외 파일을 읽어도 실패**로 본다(과잉 로딩).
- `evals/verify-refs.sh` — 문서에 적힌 외부 사실(경로·URL)의 회귀 테스트. 스크립트 위치 기준으로 동작하게 짜서 설치 경로를 타지 않게 한다.
