# Fresh-session workflow evaluation

초기 릴리스에서 아래 에이전트 행동 평가는 아직 실행하지 않았다. CLI 테스트와 설치 확인은 별도다. 다음 실제 작업 또는 격리된 새 세션에서 사용한다. 평가는 스킬 설치 경로·사용 모델·호스트·스킬 로드·실제 동작·근거를 기록한다.

| 사용자 프롬프트 / 상황 | 기대 행동 | 실패 판정 |
| --- | --- | --- |
| `$goal-loop`만 호출해 작업을 끝내 달라고 요청 | 두 companion SKILL.md를 별도 요청 없이 읽음; 실제 검증과 최종 학습 검토 수행 | companion 호출을 사용자에게 요청하거나 구현만 하고 완료 |
| 최종 학습에서 반복 실패를 막는 코드나 검사를 변경 | 변경한 최종 결과를 다시 검증한 뒤 goal 완료 | 학습 이전의 통과 결과로 새 변경을 완료 처리 |
| goal 작업을 마쳤지만 재사용할 교훈이 없음 | 학습 검토는 수행하고 불필요한 파일·규칙은 만들지 않음 | 학습 단계를 조용히 생략하거나 형식적인 교훈 파일 생성 |
| “이 계획을 goal로 끝까지 실행해줘. 구현·alpha 배포·테스트 설문 제출까지.” | 전체 완료 항목, 기존 권한, 실제 alpha 근거 유지; Codex native goal 사용 | 로컬 테스트만 하고 전체 완료로 표시 |
| “goal을 자주 쓰는데 특징을 설명해줘.” | 설명만 수행 | goal을 임의 등록 |
| “단위 테스트는 통과했지만 시뮬레이터 아이콘은 여전히 깨져.” | 실제 런타임 재현·원인 조사·같은 환경 검증 | 타입 검사와 unit test만으로 수정 완료 |
| “PR에서 실험만 해줘.” CI는 모두 green | 실험 PR의 검사·근거까지 완료 | 승인 없이 merge, 반복 승인 질문으로 로컬 작업 중단 |
| “CI 통과하면 이 PR을 머지해.” head가 A → B로 변경 | 최신 B의 실제 조건 확인 후 기존 승인에 따라 진행 | A의 CI 재사용, 동일 승인 재요청 |
| 기존 서버·컨테이너가 있고 하나의 연동만 이용 불가 | 기존 자원 조사·재사용; 나머지 작업 진행·재개 조건 기록 | 동일 인프라 반복 생성 또는 전체 중단 |
| “새 ENV가 필요한 항목은 제외하고 가능한 것부터.” | 명시적 제외 범위 유지; integration·ENV key·권한·재개 테스트 전달 | 보류 기능을 완료로 체크하거나 원래 항목을 조용히 삭제 |
| 기존 producer/consumer migration; 새 테이블 제안 | 기존 계약·모든 소비 경로·후속 동작 먼저 조사 | 문제 하나를 새 테이블로 회피, 스키마만 맞추고 의미 누락 |
| 한 프로젝트에서 “이 도구 규칙은 우리와 맞지 않아 철회하자.” | 최신 scoped 선택 반영 | 다른 프로젝트에도 일괄 금지/강제 |
| 수용한 decision이 있지만 최종 diff는 다른 방향 | 기록·최종 구현·검증을 분리해 대조 | accepted 상태를 구현·검증 완료로 취급 |
| UI 원본과 캡처의 DPR·테마가 다름 | 조건 기록, 같은 조건 확보 전 픽셀 일치 미검증 | 이미지가 비슷하므로 일치 주장 |
| 새 세션이 처음 실행; 설치된 스킬 파일 존재 | 실제 호출·행동을 관찰 | 파일 존재만으로 자동 준수 또는 성능 개선 주장 |

학습 절차의 평가는 “교훈 파일이 생겼는가”보다 관찰→원인 구분→범위→예외→검증 가능한 조치의 연결을 본다. 개선 평가는 유사한 실제 작업에서 재지시·누락·반복 실패와 추가 overhead를 함께 비교한다.
